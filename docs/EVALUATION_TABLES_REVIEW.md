# Review of `Evaluation_Tables_FINAL_1.docx` against the notebook and its run log

This is a line-by-line check of every table in the evaluation document against
(a) the code in `gatcnn.ipynb` and (b) the outputs stored in that notebook from
its Kaggle run of 2026-07-13 (papermill duration 39,431 s).

Three kinds of problem were found:

| Kind | Meaning | Count |
|---|---|---|
| **A. Number does not match the run** | The table cites a value the notebook did not produce | 6 tables |
| **B. No code produces it** | The table cites a quantity nothing in the notebook computes | 4 tables |
| **C. Internal contradiction** | Two tables disagree with each other | 1 pair |

Every issue below is addressed in this repository: either the code now computes
the quantity, or `cxr_gnn/evaluation/tables.py` regenerates the table from saved
artifacts so the numbers cannot drift from the run again.

---

## Table 1 — Split configurations and bootstrapped CIs

**Type A.** The confidence intervals do not match the notebook's own output.

| Config | Document | Notebook run (Step 19) |
|---|---|---|
| S1 | 0.789 (0.740–0.835) | 0.782 (0.733–0.828) |
| S2 | 0.779 (0.741–0.816) | 0.786 (0.748–0.824) |
| S3 | 0.789 (0.740–0.835) | 0.775 (0.726–0.821) |
| S4 | 0.807 (0.758–0.853) | 0.793 (0.744–0.839) |
| S5 | 0.795 (0.760–0.828) | 0.793 (0.760–0.826) |

Every S1–S4 row differs. S1 and S3 are also given *identical* accuracy CIs in
the document while their point estimates differ, which cannot happen with
independent bootstraps.

**Also:** the caption says "S4 … is used as the primary split throughout", but
the notebook's `Config` used `test_size=0.10, val_size=0.10` — that is S1
(80/10/10), not S4. The headline test result came from a different split than
the one the document claims is primary.

*Fixed:* `Config.val_size` is now `0.20`, so the primary split really is S4, and
Table 1 is regenerated by `tables.table1_split_configs()` straight from
`split_sensitivity.json`.

## Table 2 — 5-fold cross-validation

**Type A.** Four of five folds disagree with the run log:

| Fold | Document acc. | Notebook acc. |
|---|---|---|
| 1 | 0.7864 | 0.7670 |
| 2 | 0.8252 | 0.7961 |
| 3 | 0.8350 | 0.8252 |
| 4 | 0.7549 | 0.7549 ✓ |
| 5 | 0.7843 | 0.7941 |
| Mean | 0.7972 ± 0.0293 | **0.7875 ± 0.0246** |

The document's fold-2 and fold-3 values look like the run's fold-3 and a
shifted copy — consistent with rows having been transcribed out of order.

**Type B.** The table has an MCC column; `run_cross_validation()` never computed
MCC per fold. *Fixed:* it does now, and MCC is logged and stored per fold.

## Table 3 — Per-class performance

**Type A + mixed provenance.** The support column (70/25/95/70/25 = 285) is the
S4 test set pooled over 5 seeds. But the sensitivity/specificity/PPV/NPV values
are taken from the notebook's SAP 6.2 block, which reports **out-of-fold
predictions over 513 graphs from the GATv2 model**, a different experiment. The
two cannot be combined into one row. Where they can be compared, they disagree:

| Class | Document sens. | Notebook 6.2 sens. |
|---|---|---|
| Cardiac | 0.734 (0.652–0.803) | 0.734 (0.652–0.803) ✓ |
| Chronic Lung | 0.800 (0.662–0.891) | 0.778 (0.637–0.875) |
| Normal | 0.731 (0.660–0.792) | 0.749 (0.679–0.808) |
| Pleural | 0.886 (0.760–0.950) | 0.909 (0.788–0.964) |
| TB | 0.912 (0.849–0.950) | 0.912 (0.849–0.950) ✓ |

**Type B.** The LR+ and LR− columns are computed nowhere in the notebook.
*Fixed:* `stats.per_class_sens_spec_ppv_npv()` now returns likelihood ratios,
prevalence and per-class AUC, and Table 3 is built from the **pooled best-split
predictions** — the same source as Table 4, so the two agree by construction.

**Footnote error.** The caption refers to "the 19-image TB and Pleural minority
classes". TB has 139 images and is one of the *larger* classes; the minority
classes are ChronicLung (50) and Pleural (49). Neither has 19 images.

## Table 4 — Confusion matrix

**Type C — contradicts Table 3.** Recall in Table 4 and sensitivity in Table 3
are the same quantity, computed on the same 285 predictions. They differ:

| Class | Table 3 sensitivity | Table 4 recall |
|---|---|---|
| Cardiac | 0.734 | 0.700 |
| Chronic Lung | 0.800 | 0.840 |
| Normal | 0.731 | 0.779 |
| TB | 0.912 | 0.900 |
| Pleural | 0.886 | 0.920 |

Table 4 is at least internally consistent (230 correct of 285 = 0.807, matching
its own precision row and Table 7c's 55 errors). Table 3 is the one carrying
foreign numbers.

*Fixed:* both tables are now generated from one array of pooled predictions
(`split_sensitivity.json → pooled_predictions_best_split`), so they cannot diverge.

## Table 5 — Statistical significance

**Type A.** The split-ratio rows contradict the run. The document has S1 accuracy
0.7895 and S2 0.7788, giving Δ = +0.011; the notebook's own S1 and S2 means were
0.782 and 0.786, i.e. Δ negative.

**Type B.** Two problems with the model-vs-model rows:

1. The statistic is reported as a signed z (−4.49, −3.11, +0.29 …), but
   `delong_test_macro()` returned a **Fisher-combined chi-square**, which is
   strictly positive and cannot be negative. The signed values have no source.
2. The row "GCN vs ResNet18" was never computed: `_run_stat_tests()` only
   compared the primary model against each other model, never other pairs.

*Fixed:* `delong_test_macro()` now additionally returns a Stouffer-combined,
signed `z_macro` (so a signed statistic is legitimate), and `_run_stat_tests()`
runs **all** pairwise comparisons with Holm and BH correction over the whole
family. A guard also refuses to run a paired test when the two models' held-out
label vectors are not identical.

## Table 6 — Model comparison

**Type A** on every metric. Discrimination columns vs the run log:

| Model | Doc acc / F1 / AUC | Notebook acc / F1 / AUC |
|---|---|---|
| GATv2 Hybrid | 0.807 / 0.805 / 0.956 | 0.801 / 0.801 / 0.961 |
| GAT | 0.798 / 0.794 / 0.951 | 0.813 / 0.812 / 0.963 |
| GraphSAGE | 0.802 / 0.799 / 0.958 | 0.811 / 0.805 / 0.961 |
| GCN | 0.819 / 0.816 / 0.962 | 0.826 / 0.820 / 0.965 |
| ResNet18 | 0.868 / 0.862 / 0.968 | 0.873 / 0.857 / 0.980 |

MCC, kappa and ECE are off by similar margins (e.g. GATv2 ECE 0.118 in the
document, 0.128 in the run; GAT 0.156 vs 0.173).

**Type B — and a factual error.** The Params / Train (min) / Infer. (ms) columns
were computed nowhere. Worse, "GATv2 Hybrid — 11.4 M parameters" is wrong by two
orders of magnitude: the notebook printed **79,293 trainable parameters**, and
the frozen encoder adds 683,072 non-trainable ones. 11.4 M is roughly a full
ResNet18 — a model the hybrid never trains. As written the table hands the
efficiency argument to the CNN baseline on a number that is not real; the
hybrid is in fact ~140× smaller in trainable parameters.

*Fixed:* parameter counts, per-fold training seconds and median single-graph
inference latency are now measured in `run_model_comparison()`, and Table 6
labels the count explicitly as *trainable* parameters.

## Table 7a — Ablation

**Type B.** Four of six rows have no implementation. The notebook's ablation had
exactly four arms — hand-only, deep-only, hybrid+edge, hybrid no-edge — and
reported:

```
Hand-only (12d)  acc 0.587    Deep-only (128d) acc 0.825
Hybrid   (140d)  acc 0.805    Hybrid no-edge   acc 0.789
```

The document instead lists "− GATv2 → GCN layer", "− Attention heads (1 head)",
"− Class weighting / sampler" and "− ImageNet pretraining", none of which existed
in the code, and drops the feature-ablation results that did.

*Fixed:* `training/ablation.py` implements all of them — `GATv2SingleHead`, a
`balanced=False` path through the trainer that disables both the sampler and the
loss weights, `build_encoder(pretrained=False)` for the pretraining arm, and the
raw-pixel CNN as the "no superpixel graph" arm — plus the original feature arms.

**Sign convention.** The "− Superpixel graph" row shows Δ Acc = **+0.061** under
a heading that reads as a removal penalty. The sign is right (removing the graph
*helps*) but the presentation invites the opposite reading. The regenerated table
states the convention explicitly.

**Also:** the docstring in `data/graph.py` quoted ablation numbers
(61.6 / 81.6 / 80.2 / 82.1) that match neither the document nor the run log.
Removed rather than corrected — narrative results do not belong in a module
docstring.

## Table 7b — Robustness under perturbation

**Type B, entirely.** No noise, JPEG, rotation, brightness or contrast experiment
exists anywhere in the notebook. All seven rows, the retention percentages and
the A/B/C grades are unsourced.

*Fixed:* `evaluation/robustness.py` implements every perturbation, rebuilds the
graphs through the identical SLIC + encoder path, and computes retention and
grades with the thresholds the document states.

## Table 7c — Error analysis

**Type B.** No code produced the confusion-pair counts, the mean confidences, or
the claim that "an abstain threshold at conf < 0.55 would defer 61% of errors".
The counts are at least arithmetically consistent with Table 4 (55 errors, 230
correct, 285 total).

*Fixed:* `evaluation/error_analysis.py` computes the taxonomy, per-pattern mean
confidence, and both sides of the abstention trade-off — including how many
*correct* predictions the threshold would also defer, which the document omits
and which is what makes an abstention rule costly.

## Table 8 — Literature benchmarking

Mostly sound; the caveat paragraph is appropriately worded. Two issues:

- The MIMIC-CXR row is dated "2026" and the two "ours" rows likewise. A year
  should not be in the future relative to the work; cite the actual publication
  year of the benchmark.
- `evaluation/reporting.py` described this project's dataset as "~479-image" in
  a docstring while the run collected **570** images. *Fixed.*

## Cross-cutting: which experiment is the headline?

The document reports the GATv2 hybrid at accuracy 0.807. The notebook produced
three different accuracy numbers for it, from three different experiments:

| Source | Accuracy |
|---|---|
| Held-out test set (Step 9, 57 images) | **0.8246** |
| 5-fold CV (Step 11, 513 graphs) | 0.7875 |
| Out-of-fold in the baseline comparison (Step 13) | 0.801 |

None is 0.807. Pick one as the headline, state which, and use it consistently —
`test_results.json` is the natural choice, and Table 8 now pulls from it directly.

## The finding the document gets right

The central honest conclusion — that the fine-tuned ResNet18 CNN baseline
**beats** the hybrid GNN on every axis including cost, and that the graph
variants are statistically indistinguishable from each other — is supported by
the run log, correctly signed, and correctly labelled as significant after Holm
correction. It survives all the corrections above. That conclusion should stay
prominent; it is the strongest thing in the document.
